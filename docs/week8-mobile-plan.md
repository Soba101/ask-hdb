# Week 8-4: Google Maps-style phone layout

## Goal
On phones (width 800px or less) the app feels like Google Maps: a full-screen map, a floating search bar, a row of layer chips, and one bottom sheet that holds everything else. Desktop (above 800px) is unchanged.

## Mechanism
`sheet.js` is a no-op above 800px. On `matchMedia("(max-width: 800px)")` it moves existing nodes with `append` (never clone: every id stays unique) and restores each to its original parent and position when the query stops matching. Nothing is rebuilt.
- **The sheet is `#side`** (fixed to the bottom, full width). Its height is animated through a `--sheet-h` CSS variable (height, not `transform`, so fixed children keep working).
- **Moves on phones:** `#form` (holding `#question` and Send) goes to a new empty `<div id="topbar">` in `#mapwrap` (the floating search bar, the only chat input; none at the sheet's foot); `#card` goes to the top of `#side`; the `.seg` row, `#toggle-3d` and the price controls go to a new `<div id="chips">` under the search bar; `#sun-panel` goes to a new `<div id="sun-bar">` above the sheet. Moving them out of the closed `<details class="view-options">` is deliberate: iOS never renders content of a closed details. The `.legend` goes into the sheet header's peek area (below the title). The empty-peek text ("Ask about a flat, a grant or a place") is a new `<p id="peek-hint">` in the sheet header, shown only when nothing is selected.
- **Also moved on phones:** `#selected` (the "Asking about" chip, a sibling of `#form`) goes to `#topbar` beside `#form`. `#price-controls` and `#lease-controls` go to a sub-row `#chip-detail` under the chips, each shown only while its layer is active. The "About this layer" details (`#layer-note`), `#building-error` and the long limits paragraph of `#sun-panel` (given its own id `sun-limits`, moved as a node) go into a new `<div id="sheet-notes">` inside `#side`, after the card, so every limit text stays in the sheet. `#sun-panel` keeps only the date input, time slider, Now, Play and the position line in the sun bar. The emptied `#layers` and `#map-controls` stay in the DOM, hidden by CSS while empty. Mode buttons are found with `.seg [data-mode]` instead of `#layers [data-mode]` (`app.js` lines about 248 and 292), a change that is also valid on desktop. Any `style.css` rule keyed on `#layers` or `#map-controls` is re-checked for the moved nodes.
- **Removed:** the earlier Layers button, overlay and `initLayers` logic in `buildings.js` (its Escape, outside-tap and focus hand-off handlers would fight the sheet), and the card's own fixed 58dvh phone positioning. `tests/mobile_ui.mjs` is rewritten for the sheet; its width/resize cases are kept.

## Layout (800px or less)
- **Map:** full screen. Zoom/tilt controls (top right) sit below the chip row; attribution, `.mapnote` and the bottom MapLibre controls are offset by `--sheet-h`.
- **Search bar:** floating, full width with safe-area insets. Tapping it raises the sheet to full on the Chat tab. The "Asking about" chip and its clear button sit inside it.
- **Chip row:** horizontal scroll, no scrollbar: Type, Price, Lease, 3D. Price keeps its flat-type select and budget slider in a short row that appears under the chip when Price is active.
- **Sheet snap points:** peek (about 112px: handle, title and headline figures of the selection or the peek hint), half (50dvh), full (92dvh). Drag the handle or header; release snaps to the nearest point (no velocity bias); tapping the handle steps up, wrapping from full to peek. The keyboard: `visualViewport` resize sets a `--kb` inset used by the sheet's bottom and max height (iOS `dvh` does not shrink with the keyboard).
- **Gestures:** pointer capture on the handle and header only, about 8px move threshold so a tap on the Chat/Evidence buttons stays a tap, `overscroll-behavior: contain` on the sheet content, and `touch-action: none` on the handle only, so the map still pans and content still scrolls.
- **Selection:** choosing a place sets the sheet to peek with the card summary; opening a section chip raises it to half; closing the card returns to the chat peek; a chat answer raises it to half. Map padding (`setPadding` bottom = sheet height) is applied only when a snap ends, never per drag frame, and `fitBounds` in `app.js` passes the bottom inset explicitly so a fitted view clears the sheet. Selecting a place does not move the viewport (existing contract).
- **Sun and 3D:** the bar docks above the sheet only when 3D is on; the existing limits text stays where it is in the panel (no new disclosure).

## Rules
- Same DOM ids and behaviours as docs/week8-plan.md. No `innerHTML`, no new dependency, no network or API change, no agent, tool or prompt change. Desktop DOM, order and behaviour unchanged (tests assert the restore).
- **Accessibility:** the sheet is a labelled region; the handle is a button whose `aria-label` names the current state ("Results, half height. Press to expand."); Enter, Space, ArrowUp and ArrowDown change the snap point; Escape steps down one point. Focus moves only when the user opens the sheet from the handle or search bar, never on a map selection. At peek, content below the fold is `inert`, and a `focusin` from outside raises the sheet to half. `#log` (`role=log`) stays live; the card summary stays the only other live region. Reduced motion removes the snap animation.
- All limits, sources and `as_of` text stay reachable inside the sheet.
