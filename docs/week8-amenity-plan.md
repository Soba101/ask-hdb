# Week 8-7: nearest supermarket, MRT and bus stop, with walking directions

## Goal
From a selected block (or any selected place), show the nearest supermarkets, MRT/LRT stations and bus stops, and on request draw a walking route with step-by-step directions and a walking time, like a maps app. Phone and desktop.

## Decisions and sources (checked 2026-10-24)
- **Routing:** OneMap routing API, route type `walk`. `GET https://www.onemap.gov.sg/api/public/routingsvc/route?start=<lat>,<lng>&end=<lat>,<lng>&routeType=walk` with the token in the `Authorization` header. Response: `route_geometry` (encoded polyline, decode with the sample code in the OneMap docs, precision 5), `route_instructions` (rows: direction word, road name, distance in metres, "lat,lng", time, text such as "Head East"; last text is the arrival line), `route_summary.total_time` (seconds) and `total_distance` (metres). Errors: 401 (refresh token once), 404 (no route), 429 (quota). The terms (onemap.gov.sg/legal/apitermsofservice.html) allow use with your own credentials kept secret, a truthful client identity, no disrupting the service, and per-API limits; the Singapore Open Data Licence applies to the data, so the card credits "Route: OneMap (SLA), walking estimate".
- **Credentials:** `ONEMAP_EMAIL` and `ONEMAP_PASSWORD` in `.env` (`geo/client.py` `load_credentials()` and `_refresh_token` already do this for geocoding; keep and reuse them, but note `OneMap._request` sleeps 0.5 s before every call, retries up to 5 times with backoff, has a 15 s timeout, retries 429 itself and raises `StopGeocoding`/`GeocodeError` for 401/403/others, so it must not be used as is for page requests: add a `route()` method with retries, timeout and sleep as parameters (one attempt, 8 s, no sleep), map the exceptions explicitly (401 after one refresh = no_credentials/unavailable, 404 = no_route, 429 = quota, other = unavailable), share one instance for the process and guard the token refresh with a `threading.Lock` because sync routes run concurrently). The token is fetched on demand, cached in memory until just before expiry, refreshed once on a 401. If credentials are missing the feature still lists the nearest places by straight-line distance and says "Walking directions need OneMap credentials in .env"; it never fails the page.
- **MRT/LRT:** stations are in `places.parquet` (kind mrt/lrt, centroid and `exit_count`). Exit coordinates are only in `data/raw/places/mrt_exits.geojson`, which `.dockerignore` excludes, so exits must be written to `data/clean` at build time: add `kind=mrt_exit` rows (with `place_id` of the station they belong to, grouped by `STATION_NA` as `build_places.py` already does) to `amenities.parquet` or to the places build. Route to the station's nearest exit by straight line; fall back to the station point with a note if a station has no exit row.
- **Bus stops and supermarkets:** no key needed: a build script `scripts/build_amenities.py` queries OpenStreetMap through the Overpass API once (Singapore bounding box, polite User-Agent that names the app, one request per kind with a timeout and a retry) and writes `data/clean/amenities.parquet` with a stable `id` (`osm:node/123`, `osm:way/456`; stations keep their `place_id`), `kind` (`bus_stop`, `supermarket`, `mrt_exit`), `name`, `ref` (the 5-digit bus stop code when OSM has it), `lat`, `lng`, `source`, `as_of`. Supermarkets: `nwr["shop"="supermarket"]` with `out center` (many are ways). Bus stops: `highway=bus_stop` and `public_transport=platform` + `bus=yes` usually sit on the same node: dedupe by OSM id first, then merge stops within 15 m with the same name. Overpass can answer HTTP 200 with a `remark` (timeout or partial data): the build fails if a remark is present or a count is below a sane floor (for example under 4,000 bus stops or under 300 supermarkets), and writes the file atomically (temp file then rename). OSM may be incomplete or stale: say so in the limits. The file is gitignored like the other data; the Dockerfile and `.dockerignore` include it like `buildings.geojson`, and the Dockerfile `RUN` line adds `test -s data/clean/amenities.parquet` next to the buildings check (same pattern). Optional later: LTA DataMall (needs the user's key) for authoritative bus stop codes.
- **No agent change.** The agent, tools, prompt and grounding rules are untouched (the 18-tool schema already nearly fills an 8k slot). The feature is UI and API only. Every number on screen comes from code or OneMap and is labelled.

## API (new `src/ask_hdb/api/amenities.py`, included from `api/__init__.py`)
- `GET /nearby/{kind}/{id}?type=supermarket|mrt|bus&n=3` (kind and id as in `/card`): the `n` nearest of that type by straight-line distance computed in code from `amenities.parquet`/`places.parquet` (haversine, existing helper), each `{id, name, ref, lat, lng, km}`; 404 for an unknown selection. Response includes `source`, `as_of`, `limits` ("Straight-line distance; OpenStreetMap data may be incomplete" for bus and supermarket).
- `GET /route/{kind}/{id}?to=<amenity id>`: looks both ends up locally (the client never sends coordinates, so the server cannot be used as a proxy to arbitrary points), calls OneMap with a 8 second timeout, and returns `{distance_m, duration_s, steps: [{text, road, distance_m}], line: [[lng,lat],...], source, limits}` with the geometry decoded server-side and steps built from `route_instructions`. Errors map to `{error: "no_credentials"|"no_route"|"quota"|"unavailable"}` with HTTP 200/404/429/502 and a plain message; the OneMap response body is never echoed. In-memory LRU cache with a `maxsize` keyed by the two ids; only successful routes and 404 no_route are cached, never quota, unavailable or no-credentials results. Limits: a per-visitor limit and a global per-minute cap that protects the shared OneMap account, using the existing `Limits` class given a `per_minute` argument (today it reads `API_RATE_PER_MINUTE`, the `/chat` setting, which must not change).
- Never log credentials or tokens; the token is not placed in any URL or response.

## UI (phone and desktop)
- In the card's **Nearby** section (exists today with counts), add a row of three pill buttons with `aria-pressed`: Supermarkets, MRT/LRT, Bus stops. Choosing one calls `/nearby` and lists the three nearest as rows (name, bus stop code when known, straight-line distance) with a "Walk" button on each; the nearest three are also marked on the map with numbered markers in their own source and layer (not the `highlight` source, which chat also writes to), cleared when the selection changes.
- The Nearby section's fixed text "Straight-line distances, not walking or travel times." is reworded so it does not contradict walking times ("Lists are ranked by straight-line distance; walking times come from OneMap routes."). Nearby today holds `nearby-facts`, the radius chips, counts and the fit button; the new pill row and route block get ids listed in docs/week8-plan.md's contract (add them there).
- Tapping Walk calls `/route`: two line layers `route-casing` and `route` are added after the `buildings` layer with `beforeId: "places"` so markers stay on top; the line is hidden under 3D buildings when the map is pitched, which the limits text for the route notes (or draw it above them if that is simple); no new dependency, the map fits the route with padding that clears the sheet (use `sheet.padding`), and the card shows a "Walking directions" block: total time and distance ("about 9 min, 650 m, walking estimate from OneMap"), then the steps as an ordered list (instruction text and distance), plus a "Clear route" button. Errors show the plain message inline (`role=status`), including the no-credentials note.
- Phone: the route block lives in the sheet; the sheet goes to half when a route loads (the peek line "to <place>, 9 min" is out of scope for now). All new buttons keep 44px touch targets. Stale-response guards like `cardRequest` for `/nearby` and `/route` so a late answer cannot draw over a newer selection. No `innerHTML`.
- Labels: "Straight-line" for the ranking, "walking estimate" for OneMap results; limits text goes in the card's "About these numbers" disclosure and inline next to the figures.
