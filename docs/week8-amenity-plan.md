# Week 8-7: nearest supermarket, MRT and bus stop, with walking directions

## Goal
From a selected block (or any selected place), show the nearest supermarkets, MRT/LRT stations and bus stops, and on request draw a walking route with step-by-step directions and a walking time, like a maps app. Phone and desktop.

## Decisions and sources (checked 2026-10-24)
- **Routing:** OneMap routing API, route type `walk`. `GET https://www.onemap.gov.sg/api/public/routingsvc/route?start=<lat>,<lng>&end=<lat>,<lng>&routeType=walk` with the token in the `Authorization` header. Response: `route_geometry` (encoded polyline, decode with the sample code in the OneMap docs, precision 5), `route_instructions` (rows: direction word, road name, distance in metres, "lat,lng", time, text such as "Head East"; last text is the arrival line), `route_summary.total_time` (seconds) and `total_distance` (metres). Errors: 401 (refresh token once), 404 (no route), 429 (quota). The terms (onemap.gov.sg/legal/apitermsofservice.html) allow use with your own credentials kept secret, a truthful client identity, no disrupting the service, and per-API limits; the Singapore Open Data Licence applies to the data, so the card credits "Route: OneMap (SLA), walking estimate".
- **Credentials:** `ONEMAP_EMAIL` and `ONEMAP_PASSWORD` in `.env` (the existing `geo/client.py` `load_credentials()` and token refresh already do this for geocoding; reuse it, do not duplicate). The token is fetched on demand, cached in memory until just before expiry, refreshed once on a 401. If credentials are missing the feature still lists the nearest places by straight-line distance and says "Walking directions need OneMap credentials in .env"; it never fails the page.
- **MRT/LRT:** already in `places.parquet` (kind mrt/lrt, with `exit_count`); the raw `mrt_exits.geojson` has exit coordinates: route to the nearest exit of the chosen station, not the station centroid, if the exits file joins cleanly by station name; otherwise the station point with a note.
- **Bus stops and supermarkets:** no key needed: a build script `scripts/build_amenities.py` queries OpenStreetMap through the Overpass API once (Singapore bounding box, polite User-Agent that names the app, one request per kind with a timeout and a retry) and writes `data/clean/amenities.parquet` with `kind` (`bus_stop`, `supermarket`), `name`, `ref` (the 5-digit bus stop code when OSM has it), `lat`, `lng`, `source`, `as_of`. Supermarkets: `shop=supermarket`; bus stops: `highway=bus_stop` or `public_transport=platform` with `bus=yes`. Dedupe stops within 15 m with the same name. OSM may be incomplete or stale: say so in the limits. The file is gitignored like the other data; the Dockerfile and `.dockerignore` include it like `buildings.geojson`, and the build step fails loudly if it is missing (same pattern as the buildings file). Optional later: LTA DataMall (needs the user's key) for authoritative bus stop codes.
- **No agent change.** The agent, tools, prompt and grounding rules are untouched (the 18-tool schema already nearly fills an 8k slot). The feature is UI and API only. Every number on screen comes from code or OneMap and is labelled.

## API (new `src/ask_hdb/api/amenities.py`, included from `api/__init__.py`)
- `GET /nearby/{kind}/{id}?type=supermarket|mrt|bus&n=3` (kind and id as in `/card`): the `n` nearest of that type by straight-line distance computed in code from `amenities.parquet`/`places.parquet` (haversine, existing helper), each `{id, name, ref, lat, lng, km}`; `n` 1 to 5. 404 for an unknown selection. Response includes `source`, `as_of`, `limits` ("Straight-line distance; OpenStreetMap data may be incomplete" for bus and supermarket).
- `GET /route/{kind}/{id}?to=<amenity id>`: looks both ends up locally (the client never sends coordinates, so the server cannot be used as a proxy to arbitrary points), calls OneMap with a 8 second timeout, and returns `{distance_m, duration_s, steps: [{text, road, distance_m}], line: [[lng,lat],...], source, limits}` with the geometry decoded server-side and steps built from `route_instructions`. Errors map to `{error: "no_credentials"|"no_route"|"quota"|"unavailable"}` with HTTP 200/404/429/502 and a plain message; the OneMap response body is never echoed. In-memory LRU cache keyed by the two ids for the process lifetime (routes do not change minute to minute) and a per-visitor rate limit separate from `/chat` (the existing limiter class, for example 20 per minute).
- Never log credentials or tokens; the token is not placed in any URL or response.

## UI (phone and desktop)
- In the card's **Nearby** section (exists today with counts), add a row of three pill buttons with `aria-pressed`: Supermarkets, MRT/LRT, Bus stops. Choosing one calls `/nearby` and lists the three nearest as rows (name, bus stop code when known, straight-line distance) with a "Walk" button on each; the nearest three are also marked on the map with a numbered ring (same ring layer approach as the school rings, cleared when the selection changes or the chat sets a highlight, chat wins).
- Tapping Walk calls `/route`: a line layer `route` draws the path (blue line, white casing, no new dependency), the map fits the route with padding that clears the sheet (use `sheet.padding`), and the card shows a "Walking directions" block: total time and distance ("about 9 min, 650 m, walking estimate from OneMap"), then the steps as an ordered list (instruction text and distance), plus a "Clear route" button. Errors show the plain message inline (`role=status`), including the no-credentials note.
- Phone: the route block lives in the sheet; the sheet goes to half when a route loads; the peek shows "to <place>, 9 min". All new buttons keep 44px touch targets. Stale-response guards like `cardRequest` for `/nearby` and `/route` so a late answer cannot draw over a newer selection. No `innerHTML`.
- Labels: "Straight-line" for the ranking, "walking estimate" for OneMap results; limits text goes in the card's "About these numbers" disclosure and inline next to the figures.
