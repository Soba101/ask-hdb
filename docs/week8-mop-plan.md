# Week 8-6: MOP status on the map, and upcoming BTO completion

## Goal
Mark blocks that have not yet reached the Minimum Occupation Period (MOP) and show upcoming BTO sites as upcoming, with an estimated completion. Everything is approximate and labelled so.

## What the data can say (checked 2026-10-24)
- Built blocks: `resale.parquet` has `lease_commence_year` per sale. HDB's MOP is 5 years from key collection for standard flats and 10 years for Plus and Prime flats. Both values are in `rules/bto/2026-10.yaml` (`mop.standard_years` = 5, `mop.plus_prime_years` = 10, each with source and as_of), not in `rules/2026-10.yaml`: load them with `load_rules(BTO_FILE)` from `ask_hdb/rules/bto.py` and cite with `Rules.cite()`. Resale blocks use `standard_years`; the resale data cannot tell Plus/Prime blocks apart, and in practice none is resold yet (10-year MOP, newest lease start 2023). The limits text says this instead of claiming 5 years for every flat. We have no key-collection date, so the lease start year stands in for it. A block with lease start Y reaches MOP during year Y+5, month unknown.
- Newest lease start in the data is 2023, and a block appears only once a flat in it has resold. Blocks finished recently and never resold are not in `blocks.parquet` sales and cannot be marked; the limits text says so.
- BTO: `bto_projects.parquet` has `first_launch` (YYYY-MM) and `wait_months` (HDB's stated waiting time from launch). Estimated completion = first_launch + wait_months, shown as a month and labelled an estimate. It is the date flats are expected to be ready, not a promise.
- Resales before MOP exist (see memory note early-resale-puzzle): a "within MOP" block can still show resales. The label says "estimated".

## Design
- **Server (code decides).** `src/ask_hdb/api/mapdata.py`: `metrics()` rows become `[price, count, lease_left, mop]` (the 4th element is safe: JS reads only indices 0 to 2) where `mop` is a small integer computed in Python from the block's newest `lease_commence_year` and the data's latest month year: 0 = "within MOP" (Y+5 > current year), 1 = "MOP ends around YYYY" (Y+5 equals the data's latest year, month unknown; the label shows that year explicitly because "this year" means the data's year, not the viewer's), 2 = "past MOP" (Y+5 < current year). The response also carries `mop_years`, `mop_rule` (the `Rules.cite()` citation) and `mop_limits` as separate keys; do not add to `limits` (the card's Prices section prints all of `limits` and `app.js` reads `limits[2]` by index). `metrics()` is `lru_cache`d and `load_rules` is cached, so read the MOP years through one small module-level getter (for example `_mop_years()`), which tests monkeypatch followed by `metrics.cache_clear()`. Existing consumers read `row[0..2]` only, so adding a fourth element is compatible; tests assert the old three fields are unchanged. The block card (`_block_facts`) gets a fact: "MOP: estimated within MOP / ends this year / past, from the lease start year" with an inline "approximate" qualifier. The BTO card gets "Estimated completion: about YYYY-MM (launch month plus stated waiting time)" beside the existing waiting time fact; no new numbers are computed outside code. Omit the fact when `first_launch` is missing or does not parse, or `wait_months` is missing. If the estimate is earlier than the data's latest month, do not call the site upcoming: say "estimated completion has passed; check HDB".
- **Map.** A fourth layer button "MOP" (`data-mode="mop"`) in the existing colour-by control and the phone chip row (`.seg [data-mode]` selectors already generic): within MOP amber, ends this year light amber, past MOP the normal blue, no data grey. The 3D buildings use the same colour expression: `buildings.js` `stateExpression` and `setFeatureState` must also handle `mop` (today only `price` and `lease`), and `mapLayer.layer` (`app.js` about line 421) sets `f.properties.mop` with default -1. Legend steps under the layer (like `#lease-controls`): a new `#mop-controls` row with the three states and one line of limits; the long limits text lives in `#layer-note`, which already moves into the sheet on phones. BTO sites keep the orange point (every listed site is upcoming, so no extra ring) with the legend text "BTO site (upcoming, approximate)".
- **No agent change.** The agent, tools, prompt and grounding rules do not change. (A later tool for "which blocks are within MOP" is out of scope.)
- Limits text on the layer and the card: "MOP is 5 years from key collection. We only know each block's lease start year, so this status is approximate (a block can reach MOP months earlier or later). Blocks with no resale yet are not shown. Check HDB for a specific flat." Read the 5 from the rules loader.
